# VCX 2.3.0

VCX 2.3.0 is a backward-compatible feature release of the guided Windows x64
package. It adds short-path media processing and durable, stage-level job
recovery across VCX processes.

## Highlights

- Run compression and subtitle generation through short, per-user VCX workspaces
  while keeping source media and planned final filenames unchanged.
- List saved jobs with `vcx jobs list` and resume a selected job with
  `vcx jobs resume <job-id>`; the TUI also offers recovery for interrupted jobs.
- Recover stages independently. Valid final outputs are reused, valid staged
  artifacts may be published, and incomplete or stale stages restart from the
  beginning. Recovery does not checkpoint inside FFmpeg or Whisper.
- Prevent concurrent recovery of the same job and safely publish validated
  outputs without replacing existing files, including tested cross-volume
  publication.
- Support paths beyond legacy Win32 `MAX_PATH` where Windows, the filesystem,
  and the complete external toolchain permit them. This is not an unlimited-path
  guarantee; component and tool-specific limits still apply.

## Install and offline behavior

Download `vcx-2.3.0-windows-amd64.zip` and its adjacent `.sha256` file from the
[VCX 2.3.0 GitHub Release](https://github.com/maucabreradev/video-compressor-extended/releases/tag/v2.3.0).
Verify the checksum, then extract the complete archive to a per-user directory
such as `%LOCALAPPDATA%\Programs\VCX`. No administrator rights or system `PATH`
changes are required.

The package bundles the pinned whisper.cpp runtime and default model with their
notices. FFmpeg/FFprobe remain consent-based, pinned downloads because the
selected GPLv3 build is not redistributed. A first run needs network access
unless the verified FFmpeg runtime is already cached. Offline setup reports
missing assets and does not start processing; verified cached assets continue
to work offline.

Job manifests and workspaces are local to the current Windows account. Keep
`%LOCALAPPDATA%\vcx\jobs` and `%LOCALAPPDATA%\vcx\work` when replacing the
application if you want to retain recoverable jobs. VCX cleanup never removes
source media or completed final outputs.

## Supported platform and acceptance boundaries

- Windows x64.
- AMD AMF is selected only after a successful real capability probe. Otherwise
  VCX offers software H.264 with a performance warning and separate confirmation.
- Linux/VAAPI, macOS, Intel Quick Sync, NVIDIA/CUDA, and AV1 are not supported.
  Ubuntu CI validates source portability only.
- Task 045 passed a packaged run with a 465-character final destination path
  containing spaces and Unicode; path components remained within 255 UTF-16
  units. This recorded case does not establish support for every path or tool.
- Cross-volume publication passed from a per-user workspace on C: to a distinct
  NTFS volume on F:. Do not generalize this result to every filesystem or volume.
- Real AMF evidence applies only to the exact Windows, GPU, driver, and FFmpeg
  combination recorded in the acceptance evidence. Mocked tests do not prove
  hardware support.

## Acceptance

- The Windows x64 package was built with the version-matched packaging script;
  repeated executable builds matched under the Go 1.25.0 toolchain used by CI,
  and the external checksum and internal archive manifest were verified.
- Clean-profile packaged processing passed on Windows 11 Pro `10.0.26200` with
  an AMD Radeon RX 5500 XT, driver `32.0.21045.16010`, and manifest-pinned
  FFmpeg 9.0.2. The real `h264_amf` capability probe and packaged encode passed.
- Packaged long-path, numbered-retry, source-preservation, and second-process
  recovery checks passed. The release-candidate CLI test used a 433-character
  destination and published from C: to a distinct NTFS volume on F:.
- The upgrade smoke test preserved per-user preferences and runtime data while
  moving from the 2.2.0 archive to 2.3.0, and preserved discoverable job
  manifests and workspace files across package replacement.
- Offline download failure and verified-cache reuse passed deterministic runtime
  asset tests. The Windows package CI separately verifies the software H.264
  fallback on a runner without usable AMF.
